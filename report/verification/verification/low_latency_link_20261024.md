# 实体旋钮联动延时优化

> 后续更新：本次记录中的临时 921600 版本现已完成 Flash 固化及真正断电启动验证，详见 `high_speed_flash_20261024.md`。下方部署段保留首次 JTAG 验证时的历史状态。

## 修改与边界

- GUI 联动模式按 3.25 个已确认 DDS 周期请求触发附近的原始样本，范围 256～16384 点；100 kHz / 25 MSPS 对应 813 点。
- 联动模式每次采集完成后通过 Qt 单次回调立即提交下一次请求，周期调度改为 33 ms，采集未完成时的状态轮询间隔为 2 ms。完整记录模式保留原先策略。
- 连接优先使用 921600；该速率握手超时后回退 115200，并显示实际连接速率。不自动开启或改写 DDS 参数。
- 唯一启动入口 `启动示波器界面.cmd` 预选 COM12、921600 和实物联动；正式 CLI 支持 `--linked --port --baud`。
- `build_scope_board.py` 增加硬件波特率参数，Tcl 使用综合 generic 配置 UART，顶层原来的 115200 默认值保持。构建目录继承工作区 ACL，解决 Python 3.14 私有临时目录在本机拒绝 vendor 子进程访问的问题。

## 固件证据

构建报告：`FPGA/reports/board/20261024_160120/manifest.json`。

- 目标 xc7a35tcsg324-1，25 MSPS、16K BRAM、UART 921600。
- 常规管脚级仿真 PASS：独立比较全部 16384 个冻结样本及 UART 首尾共 128 点。
- 上电默认配置仿真 PASS：验证未发送配置命令时的启动预设、手动 OFF→ON 门控及首尾采样读回。
- 综合、布局布线、时序和 DRC 检查通过，bitstream 已生成；没有修改 ADC/DAC 采样时钟和接口管脚。
- 用户确认 SW0=OFF 后，通过既有 guarded Tcl 进行 JTAG 易失配置加载；`program_low_latency.console.log` 含 `BOARD_PROGRAM_DONE 1` 和 `BOARD_PROGRAM_PASS`。
- 用户随后确认 SW0=ON、模块供电正常，才进行以下实物采集。

## 实测结果

`tmp/ui-knob-link/low-latency-benchmark.json`：实际 COM12 / 921600，连续采集 24 帧、每帧 813 点；除去前两帧，中位采集耗时 65.126 ms，95 分位 66.234 ms。命令耗时中位数：SINGLE 15.865 ms、GET_STATUS 16.000 ms、READ_WAVE 33.254 ms。模型有效，解析错误全为 0，测试后恢复保存的普通触发参数。

`tmp/ui-knob-link/low-latency-ui-benchmark.json`：运行可见的正式 UI 类和真实串口线程，连续接收 65 帧，排除前 5 帧统计。完整 UI 更新间隔中位数 **65.007 ms**、95 分位 **65.691 ms**、平均刷新率 **15.385 Hz**；813 点/帧，实测 Vpp 约 449 mV，正弦模型有效，CRC/长度/版本/超时解析错误均为 0。

此前 115200、2000 点的实物记录中，两帧采集时间戳间隔为 `(31446059846 - 31436057880)/25000000 = 400.079 ms`。相同链路的更新周期约缩短至原来的六分之一。此前用户曾在完整“硬件串口”模式读回 16384 点，该模式的传输等待更长。

以上测量的是采集/界面更新周期，不是机械动作到像素显示的直接端到端测量。未由自动化操作实体旋钮；用户可在现已打开的 RUN 窗口内旋转检查。当前 USB 串口短请求的往返耗时约 16 ms，属于后续进一步优化的边界，不等于 FPGA 采样速度不足。
