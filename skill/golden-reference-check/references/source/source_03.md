# 提炼来源、通用性与交付边界

## 提炼前后

原工程已经包含独立 Python FFT/包络参考、自动测试和版本相关的汇总报告；但参数、硬件版本、目录、UART 协议与 UI 混在项目约定中，直接复制到另一个题目无法运行。

本工具参考以下现有思路重新实现，没有从父目录 import，也没有硬编码 EGO1、串口号、位流版本或 Qt 依赖：

| 原工程来源 | 保留的思路 | 通用化处理 |
|---|---|---|
| `PC/protocol/spectrum_reference.py` | 独立直接 DFT、明确窗函数 | N 从输入长度取得，移除 ADC 固定位移和特定 FFT IP 摘要契约 |
| `PC/protocol/envelope_reference.py` | floor 分桶、首次极值索引 | 移除 16384/800 限制、编码反相与 OTR 打包，直接处理任意长度数值 |
| `PC/protocol/summary_report.py` | 证据哈希、状态区分、缺失不填零 | 用通用 suite 与 metrics JSON，移除版本扫描、协议和 UI 依赖 |
| `PC/tests/test_spectrum_reference.py` 等 | 已知激励和异常路径 | 新增独立算法 DUT、外部程序错误、容差与结构校验、CLI 退出码测试 |

新增 FIR 参考与独立移位寄存器 FIR 示例，用来展示示波器以外的算法接入；新增独立基 2 FFT DUT 对照直接 DFT，防止仅拿同一个函数两次运行得到的结果冒充验证。

## 通用性的实际证据

1. 一个软件示例套件同时覆盖统计、包络、FIR、FFT；FIR 可用于音频滤波、图像一维滤波或传感器信号处理。
2. 输入长度由文件决定；FFT 示例 64 点，包络 7 点，历史采集 16384 点。
3. 结果来自手算文件、独立程序或既有硬件导出；模型和传输不绑定。
4. 整个文件夹可脱离原工程运行，只用标准库。
5. 报告保留原始数据、完整输出和哈希，可复查某一次测试实际比对了什么。

不声称已完成第二块真实开发板验证。未来换板卡，只需实现写 JSON 的驱动适配器；协议、DMA 和缓存一致性需由适配器自身验证。

## 本次验收范围

- 单元测试覆盖手算数值、分桶边界、冲激/直流 DFT、容差边界、形状不匹配、NaN、缺失列、重复 JSON 键、外部程序失败/超时和报告归档。
- 软件算法示例必须全部 PASS。
- 历史实物导出仅做 16384 点标称电压换算一致性检查；采集副本 SHA256 为 `a29427ea8081714d010a6d3c091a5500ca530006a135b516d55429ffddbe44b0`。
- 故意失败示例必须检出两项 FAIL 和一项 ERROR；一键验收把“正确检出预期错误”标成总验收 PASS。
- 所有实际执行结果见 `reports/`；无需访问开发板，不修改既有工程与固化镜像。

## 可提交与需继续补充的内容

如赛事要求特定的 Skill 文件格式或评价项，应再依据完整规则补齐。本交付没有冒充 PYNQ Skill，也未实现 Overlay 加载、register_map、DMA 或缓存一致性封装；这些属于后续板端接入工作。
