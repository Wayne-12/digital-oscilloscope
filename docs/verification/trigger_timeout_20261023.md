# 实物触发超时诊断与恢复（2026-10-23）

## 现象与原因

用户在 COM12 / 115200 已连接、SW0 已使能后点击 SINGLE，界面报告“等待触发超时；采集已停止”。界面日志确认 100 kHz、数字幅度 10% 的 DDS 配置已经应用（命令 0x40）。用户确认 SMA 为 AD9767 OUTA → AD9226 IN。

直接使用临时欠幅触发抓取了 16384 个真实 ADC 样本，未增大或更改板端 DDS 输出：

| 项目 | 本次原始快照 |
| --- | --- |
| 回报采样率 | 25,000,000 Hz |
| ADC 原始码范围 | 2037～2050，共 14 个码值 |
| 标称电压范围 | -6.105～25.641 mV |
| 标称峰峰值 | 31.746 mV |
| 标称均值 | +9.762 mV |
| 时域测频 | 约 99.981 kHz |
| OTR | 0 个样本 |
| 接收解析错误 | 0 |

真实输入信号幅度小且有正偏置，不能满足原来的 0 V 上升沿及迟滞条件。界面迟滞显示 0.04 V，但本次此前没有应用触发配置，板端仍是冷启动默认 8 ADC 码（约 19.54 mV）的迟滞；输入最低约 -6.1 mV，连默认触发的下侧资格门限也到不了。不能仅凭这次超时判断线缆或 ADC 故障，也不能把 DDS 数字幅度 10% 当成 ADC 端固定电压。

## 恢复与验证

1. 临时断开 UI 串口，使用 `tmp/diagnose_trigger_input.py` 诊断。欠幅触发读取成功后发送 STOP、恢复板端原触发并释放端口。
2. 重新连接 UI，将上升沿触发电平设为 0.010 V、迟滞 0.010 V，应用并执行 SINGLE，完整采集成功。
3. 执行 Autoscale，面板选择 2 µs/div、10 mV/div、垂直中心 0.010 V；触发电平 0.010 V、迟滞 0.005 V，并收到命令 0x11 确认。
4. 再次执行普通上升沿 SINGLE 成功，接收 100%。最终显示约 100 kHz、31.7 mVpp、12.2 mV RMS、49.96% 占空比，OTR 正常、PC/FPGA CRC 0、RX 溢出 0、后端错误 0。

诊断滚动面板时曾将未应用的 DDS 数字幅度字段从 10% 改到 14%；已恢复界面为 10%，期间未发送该更改，板端 DDS 维持 10%。最终 UI 保持硬件连接、STOP 单次结束、真实波形可见；未修改 FPGA 源码或重新固化 Flash。
