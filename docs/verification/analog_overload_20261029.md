- 新增 `PC/protocol/analog_acceptance.py` 与命令行入口 `FPGA/scripts/verify_analog_overload_hardware.py`。仅以真实 UART 完整帧为验收数据，检查诊断标识为 false；不发送数字注入启用命令。
- 同帧核对 16384 点原始码与 OTR、饱和样本/连续事件、FPGA 基础测量、前 1024 点 FFT 的 OTR 标志、400 桶包络及帧首/触发附近/帧尾 ROI。重复读取摘要验证帧身份与计数不变。
- DAC 扫幅限制为原生 14 位码域，保持零偏移正弦峰值不超过 8191；直流端点使用偏移 −8192 和 +8191。禁止用 DAC 数字限幅冒充 ADC 模拟过载；一旦观察到模拟异常就停止继续升幅。

## 当时未闭合的项目（历史记录）

当前旋钮位置下，即使输出到 DAC 原生码域端点，ADC 仍没有到达 raw=0 或 4095。通过软件进一步提高幅度只会受到 DAC 物理/数字输出上限约束，不能补足缺少的模拟激励。

因此该次自动采集未覆盖：两端饱和码、非零饱和样本/事件、真实 OTR、OTR 上升沿触发、异常帧包络/ROI、过载撤销后恢复与清零。正常输入重新采集成功不等于过载恢复成功。后续验收结论依据用户于2026-10-30的确认更新，见文首。

模块手册给出 ADC 标称输入范围 ±5V、50Ω；DAC 满量程约 7.5Vpp，并有实体增益旋钮，通道 A 关系式为 `A=D/16384*Amp-Amp/2`。这些是模块标称说明，不能作为当前输入电压的独立实测值。参考资料为项目内 `单路AD9226模块资料_V1.0/3_使用指南/单路AD9226模块使用手册_V1.1.pdf` 第2、7、9页，以及 `AD9767模块资料V1.0_20260715/3_使用指南/AD9767模块使用手册_V1.1.pdf` 第2、9页。[ADI AD9226 数据手册](https://www.analog.com/media/en/technical-documentation/data-sheets/AD9226.pdf)给出 OTR 与超量程以及二进制端轨码的关系；验收检查 OTR=1 的样本必须对应端轨码，端轨码本身不要求 OTR=1。

要完成缺项，需要独立信号源及输入电压观测等额外模拟条件。曾向用户解释前端量程修改方案：改变实际模拟增益/参考电压，使 ADC 在较小的输入幅度下达到满量程；不能用修改 UI 电压刻度、软件阈值或数字注入代替。该方案还涉及电路核算、电压换算和重新校准。用户了解影响后明确选择保留原量程，因此本轮不实施这一方案。

## 使用入口

在用户确认模块供电、SW0 和闭环接线就绪后，使用新的空输出目录：

```powershell
.\.venv-ui\Scripts\python.exe FPGA\scripts\verify_analog_overload_hardware.py --port COM12 --output-dir FPGA\reports\analog_overload_hardware\NEW_RUN
```

程序返回码：0=PASS，2=INCOMPLETE，1=FAIL/CANCELLED。JSON 中的 verdict、coverage、missing 和 restored 是判定依据。自动执行不调节实体旋钮。

`--source adc-input` 仅观察已经由操作者设置好的真实输入，并在观察到间歇 OTR 时测试 OTR 触发；不控制外部信号源，不自动改变 DAC 输出。它是单种输入条件的采证入口，不能单独覆盖正常→过载→恢复的完整验收。改变接线或输入前仍需明确模块允许范围与测量条件。
