# 触发超时排查与 r2 固定版本

日期：2026-10-29。PC/UI：2026.10.29-r2；FPGA：0xA4261027，能力63。

## 实机原因

本次读回的 DDS 是 100 kHz、启用、峰值 **0 码**。保存的电脑参数仍为正弦、10%（819码），与板端实际状态不一致。输入只有约 12～17 mVpp 的噪声，FPGA 测量没有有效周期。

上升沿触发阈值为 signed13 的2码、迟滞4码，要求先到 -2码以下（按标称电压约 -3.66 mV），再严格上穿6码（约15.87 mV）。三次 AUTO 帧最小值均未达到下侧门限，故 SINGLE 未触发。旧版1秒实机复现得到截图同文案“等待触发超时；采集已停止”。AUTO 连续三个16K帧均正常，时间戳不同。通信、后端错误没有新增；既有 command 错误计数为2，未清零、未隐瞒。

发现的程序缺陷：具备 AWG 能力时，标准 DDS 也走 `awg` 任务路径；此路径原先未发 `command_confirmed`，界面也未登记待保存快照，所以应用后的实际参数没有更新本地存档。重连时原先不读取 DDS 配置，旧草稿会被误认为实际值。零幅度的来源操作无法仅凭截图追溯，本次不将其归因为硬件损坏或用户误操作。

## 修复

- 标准 DDS 经 AWG 路径应用后，要求 GET_CONFIG 逐字节一致才发确认；本地文件保存提交时的参数快照，不保存随后修改的草稿。
- 连接时读回 DDS 的实际波形、频率、幅度、偏置和开关状态并显示；连接操作不会自动开启 DDS。
- 缺省采用 AUTO 供输入预览。SINGLE 按钮仍严格等待所选触发，不自动强制触发或修改触发门限；工具提示说明此区别。
- 单次等待结束使用独立通知，保留串口连接，明确当前触发上下门限以及实际 DDS 为零、关闭或直流的情况，并提供下一步操作。STOP 只确认一次。AUTO 无帧则报告采集链路问题，避免误报为边沿触发超时。

## 验证

新版同条件复现得到 `TriggerWaitExpired`，文案明确“DDS 幅度为0码”和实际触发范围，随后 AUTO 连续3帧正常。初次与新版复现均不修改 DDS/触发配置，最终读回与初始配置逐字节一致。

随后通过实际界面/worker确认路径恢复原存档的100 kHz正弦、10%幅度（819码），并确认保存成功。3次SINGLE和3次AUTO均成功，各有16384个原始样本、不同时间戳；频率99988～100013 Hz，约173～178 mVpp（标称电压换算）。错误计数无新增、PC解析错误全零。测试后STOP，DDS保留上述恢复配置。

169项PC回归通过，新增覆盖零幅度诊断、AUTO故障分类、读回显示、确认后保存、读回不匹配拒绝确认，以及等待结束的工作线程通知。Ruff通过。

证据目录：`PC/reports/trigger_timeout_20261029/`，含修复前后JSON、原始NPY、恢复后实物记录及测试日志。两版复现的AUTO原始样本文件以后一次执行为准；每个JSON中保留当次的整帧统计。

## 固化与发布

新固定包为 `releases/scope_20261029_r2/` 及同名ZIP；日常入口仍为根目录 `启动示波器界面.cmd`。r1历史包原样保留。

本次FPGA RTL、约束、IP及硬件输入41项SHA256全部与已验收固化镜像一致，BIT/BIN/MCS校验通过。修复在电脑端执行，因此保留现有Flash，不重新擦写相同镜像。本次没有重新进行Flash读回、重配置或真实断电测试；历史Flash读回与冷启动证据见 `FPGA/reports/flash/consolidated_20261029/manifest.json`。发布清单分别记录本次检查和历史证据，不能将历史冷启动表述为本次完成。

PC设置保存在电脑参数文件，不能写入FPGA配置Flash；连接后以板端读回值为准，修改DDS后需要点击“应用DDS配置”。无输入或不满足触发条件时，严格SINGLE仍可能等待结束，这是保留的预期行为。
