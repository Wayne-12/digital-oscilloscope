# 第十二步：两个创新点的仿真验证

本步增加 `FPGA/rtl/innovation`，复用 DDS、ADC/DAC 模型、捕获、触发、BRAM、min/max、FFT 和 UART RTL。

## 12.1 闭环自检、相对校准和健康指纹

### 实际仿真链路

`dds_core -> ad9767_model -> loopback_channel_model -> ad9226_model -> adc_capture`，后接实际 `relative_calibrator`、`calibration_apply`、`spectrum_analyzer`（真实 FFT IP）和 `health_compare`。

时钟为理想 10 MSPS DAC/ADC、100 MHz 处理时钟。ADC 输出延迟在不同通道分别取 3.5 ns、7 ns，仍经后续捕获边沿采集。DAC 的建立、保持、同相 ACLK/WR1 和安全首码断言保持开启。

自检的采集调度、均值/指纹特征汇聚由 testbench 模拟主机执行；拟合、显示校正、FFT 和阈值报警使用实际 RTL。它是可重现的算法/接口原型，尚未声称已经实现板上的自治自检调度器。

执行序列：

1. DAC 中码 8192，采集 4 帧、每帧 256 点；保存各帧均值、合并零点及零输入方差。
2. DAC 相对中码输出 −2048、−1536、−1024、−512、0、512、1024、1536、2048。每点平均 **2048** 个样本，再输入 RTL 拟合器。
3. 输出幅度 256、512、1024、2048、3072、4096 的低频相干正弦。频率为 39062.5 Hz：DDS FTW=0x01000000，10 MSPS；每档记录 4096 点、16 个周期。检查 ADC 峰峰值非递减，并识别上端幅度压缩/削顶平台。
4. 最高幅度档的连续 1024 点输入第十一步 FFT，基波 bin4、二次 bin8、三次 bin12。逐 bin 与独立直接 DFT 比较，形成相对谐波功率特征。
5. 单独注入 256 点强制 OTR，再验证显示校正仍逐位保留原始码和 OTR。

初次回归在种子 42 的高噪声通道发现：512 点平均的偏置误差为 18517 Q16（约 0.283 码），超过预先固定的 0.25 码上限。最终增加为每点 2048 样本，**没有放宽误差限**。失败日志保留在旧报告目录，最终验收只使用修正后完整回归。

### 固定格式与拟合公式

令 x 为有符号 14 位 DAC 相对中码偏移，y 为 ADC 有符号码均值 Q16，拟合 `y = g*x+b`。最多 32 个点，y 的范围限定为实际 ADC12 的 −2048…2047 码。

```
D = n*sum(x*x)-sum(x)^2
gain_q20 = round_away(((n*sum(x*y_q16)-sum(x)*sum(y_q16)) << 4)/D)
offset_q16 = round_away(((sum(y_q16)<<4)-gain_q20*sum(x))/(n<<4))
correction_q20 = round_away((nominal_gain_q20<<20)/gain_q20)
```

有符号除法由绝对值和正分母的 64 位 `measure_udiv` 实现，符号显式恢复；最近舍入、半值远离零。负增益表达链路反向极性，不做无符号扩展。

对 32 点，|sum x|≤2^18、|sum yQ16|≤2^32、sum x²≤2^31、|sum x*yQ16|≤2^45。分别用有符号 20、34、34、48 位累加器，保留符号及余量；后续乘积、左移与除法均显式使用有符号/无符号 64 位。点数错误、零分母、增益过小/过大、非法均值被拒绝，不能生成看似有效的校准参数。

拟合验收在第一次仿真前固定：增益误差≤525 Q20（约 0.000501 ADC码/DAC码），偏置误差≤16384 Q16（0.25 ADC码）。非线性注入档与**整数最小二乘黄金结果**逐位比较；不要求非线性链路的线性截距等于模型原始偏置参数。四帧中码零点另列，噪声存在时的零点平均容限为 1 ADC 码。

### 校准的作用范围

`calibration_apply` 为一拍弹性显示支路：

```
display_q16 = round_away(((signed_sample<<16)-offset_q16)*correction_q20/2^20)
```

结果饱和至有符号 32 位 Q16，禁止回绕。校准无效时显式旁路为原始有符号码 Q16。原始 `{OTR,3'b000,raw_code}` 和 64 位时间戳通过独立寄存器逐位转发，不参与校正运算，不覆盖原始帧。单位测试覆盖正/负校正系数、饱和、旁路、反压；闭环测试再逐点核对实际 ADC 数据及强制 OTR。

### 指纹和报警

指纹包含有效性、拟合增益/偏置、四帧零输入方差 Q16、最高幅度的压缩损失 ppm、相对二/三次谐波功率 ppm、OTR 数。谐波特征为 `(P2+P3)/P1`；它不是 ENOB，也不是完整 THD+N。

| 档位 | 相对参考通道的变化 | 预期主分类 |
|---|---|---|
| 0 | 增益 0.25、偏置0、噪声±1，基准 | 正常 |
| 1 | 只将偏置改为 +32 | 零点漂移 |
| 2 | 只将增益改为 19661/65536 | 增益变化 |
| 3 | 只将噪声改为 ±12 | 噪声上升 |
| 4 | 只启用 −700…700 的通道削顶 | 削顶 |
| 5 | 只增加三次非线性 ODD_Q16=16384 | 谐波上升 |
| 6 | 反向、增益0.1875、偏置−37、噪声±2 的复合测试档 | 极性反转优先 |
| 7 | 增益0.375、偏置+91、无噪声，学习自己的基准 | 正常 |

报警阈值均为输入配置，不固化为实物健康阈值。回归配置：偏置差>4码、增益绝对值差>10486 Q20、方差增加>4码²、压缩损失增加>50000ppm、谐波功率比增加>100ppm、OTR数增加>0。阈值等于边界时不报警，增加一个最低位时报警；这些边界均有自动测试。

保留全部报警位；主分类优先级为：无效、极性、削顶、噪声、增益、零点、谐波、正常。削顶产生的谐波不会被误归为单纯谐波故障。内限削顶可以不触发物理 ADC OTR，因此还用幅度压缩识别；强制 OTR 另外测试。

**仿真只能验证相对算法及定点误差，不能给出实物绝对增益、ENOB 或真实健康阈值。**

## 12.2 触发感知的多分辨率采集

### 原始帧与统一结果

使用 16384×16 BRAM 捕获 RTL，采样率为 25 MSPS。

捕获完成后保持原始帧冻结。`capture_moments` 统计 count、min/max、64 位 sum/square_sum、OTR 数及 CRC32，并冻结前后时间戳。

同一 `result_id` 将以下内容关联为一个捕获结果：

- 原始记录长度、CRC32 和冻结生命周期，原始帧保留在 BRAM。
- 触发索引、预/后触发点数、原始采样率及首点/触发点/末点时间戳。
- 第十步的 800 桶 min/max、两极值各自的**原帧索引**和每桶 OTR。
- 触发附近的原始 ROI 字（保留原始12位码和OTR）及可精确恢复的原帧索引和时间戳。
- 完整帧整数测量摘要。

默认压缩传输不重复发送整个原始帧；用长度、CRC 和结果 ID 引用保留在存储器中的原帧。若同时重复传全量原始记录，就无法满足本步的数据量下降目标。完整原始数据读取仍可沿用既有波形读取链路，最终共享读口仲裁留给整机集成。

### SCAP v1 容器

所有多字节整数小端。固定 128 字节头，随后允许 B/R 记录交错，末尾 F 记录。只缓冲一个最长 14 字节记录。**不能强制先发完全部桶再接收 ROI**：现有单遍 reducer 在 ROI 输出被阻塞时会停住，这样会死锁。当前采用记录交错与公平仲裁。

| 头偏移 | 内容 |
|---|---|
| 0…7 | `SCAP`、版本1、存储类型、头长128 |
| 8/12/16/20/24/28 | result_id / N / trigger / pre / post / sample_rate，各u32 |
| 32/40/48 | first/trigger/last timestamp，各u64 |
| 56/58/60 | bucket_count u16 / roi_count u16 / roi_start u32 |
| 64/68 | 原始帧 CRC32 / 测量样本数，各u32 |
| 72/80 | sum s64 / square_sum u64 |
| 88/90/92 | min s16 / max s16 / OTR数u32 |
| 96 | 1：完整帧整数矩量有效；未声明周期有效 |
| 97…127 | 保留零 |

记录：

- B：14字节，`42 | bucket_index u16 | min s16 | max s16 | min_original_index u24 | max_original_index u24 | otr u8`。桶范围从 N、B 依照第十步的 floor 整数边界恢复，不重复发送。
- R：3字节，`52 | raw_word u16`。第 j 个 R 对应 `roi_start+j`，时间戳为 `first_timestamp+roi_start+j`，按 64 位回绕。
- F：9字节，`46 | CRC32 u32 | bucket_records u16 | roi_records u16`。CRC32/ISO-HDLC 覆盖全部头和 B/R 字节，不含 F。

CRC32 使用反射多项式 `0xEDB88320`（正常形式 `0x04C11DB7`）、初值 `0xFFFFFFFF`、低位优先、最终异或 `0xFFFFFFFF`；结果按小端发送。原始字 CRC 先处理每个样本的低字节，再处理高字节，保留 OTR。容器 CRC 则按实际输出字节顺序计算。

接收端拒绝错误版本、越界、错乱的桶序号/极值索引、非法保留位、截断、CRC 和记录数不符。ROI 的显式索引、时间戳在包装入口断言验证，传输时由头和顺序恢复；有符号 ROI 值用既有 `2047-raw` 重建。

### 复用第九步传输协议

`capture_result_uart` 使用一块 1020 字节块缓存和原有 `frame_tx`。新增响应 type=0xB2，payload=`container_offset u32 + 至多1020字节容器`；帧头、CRC16、序号和 FIRST/MORE/LAST 沿用第九步规范。这里测试字节级二进制帧；位级 UART RTL 未修改，已有验收证据继续适用。

每个结果从 sequence=65530 开始，强制覆盖序号回绕。所有分段共用原帧首时间戳、采样率、触发索引。PC 先经既有 Parser 验 CRC16，再验证分段偏移、序号、标志、元数据，最后验证 SCAP CRC32。两个层级均有独立自动测试。

### 尖峰、索引与压缩验收

每个桶放置一个正满量程极值和一个负满量程极值，覆盖桶首、中、尾及相邻桶边界，同时包含大量正、负单点毛刺。其余样本仅为小幅背景。每次都用独立 Python 模型逐桶比较 min/max 及两个原始索引；逐点计数证明整帧每个输入恰好参与一次，没有遗漏、重叠或越界。

对同一 BRAM 冻结帧测试 512/1024/2048 点 ROI；逐点比较原始字、OTR、时间戳与索引，并覆盖 64 位时间戳回绕。

| ROI点数 | 容器字节 | 含全部UART帧头、偏移和CRC的字节 |
|---:|---:|---:|
| 512 | 12873 | 13289 |
| 1024 | 14409 | 14889 |
| 2048 | 17481 | 18057 |

BRAM 含传输开销的压缩门限为 40%；实际收益按桶数、ROI 和协议开销计算。

## 2026-10-23补齐通道变化下的第二创新点

通道模型 → AD9226 → ADC 捕获 → BRAM → 800 桶 → ROI/统计/CRC → UART 容器 → PC 解析。

| 配置 | 变化 |
|---|---|
| 0 | 基准增益Q16=16384 |
| 1 | 增益24576、偏置+37 LSB |
| 2 | 增益12288、反相、偏置−23、噪声±3 LSB、延迟2.25样本、一阶低通alpha=0.5 |
| 3 | 增益32768、上下限削顶到±700 LSB |

每个通道配置运行 BRAM 捕获；独立 oracle 从 DAC 输入重算通道和 ADC 流水线，再检查原始码、OTR、ROI、身份及 CRC。

更新后的回归为13个顶层、每种子83份追踪文件、30个压缩任务。定向完整创新点报告 `FPGA/reports/innovation/20261023_161534_e47dca5a/manifest.json` 已双种子PASS；每种子2211840次原始存储读回比较、35840个ROI点、48000次极值比较。5种独立检查器破坏测试见同目录 `checker_mutations.json`，全部按预期拒绝。前文旧报告的19份追踪/12个双种子任务为扩展前历史数据。
