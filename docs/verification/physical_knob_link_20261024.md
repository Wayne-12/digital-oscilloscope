# AD9767 实体旋钮与 UI 软件模型联动

## 实现

按用户澄清，操作对象是板上 A 通道实体电位器，软件演示接收实物采集数据并联动显示。未将频率、相位等参数改成屏幕虚拟旋钮。

本地 AD9767 模块原理图显示 RW1 位于 A 通道第二级 OPA690 的反馈回路，没有到数字接口的角度反馈线。实现通过现有 OUTA→AD9226→FPGA→UART 链路观察实际输出幅度。

- 新数据源“实物联动演示”走正式串口采集路径，不接受离线演示帧。
- 青色为真实 ADC 采样；金色为该帧实测数据驱动的正弦拟合模型。信号弱、周期不足、削顶、OTR、非正弦时清空软件模型，保留实测波形。
- 右侧显示实际 Vpp、相对参考幅度及上次更新时间；STOP、断线状态明确显示，参考在新 DDS 配置确认、模式切换和重连后清除。
- 联动模式使用欠幅自动快照：门限 16383 LSB，观察 2 点，覆盖 12 位 ADC 最大跨度 4095，避免幅度降低导致边沿触发不成立。该临时配置不写入普通触发存档，触发面板在联动模式禁用。
- 每次从触发点附近读回约 8 个已确认 DDS 周期，限制在 1024～16384 点；READ_WAVE 使用协议已有的 offset/count，不改变固件、CRC 或帧格式。严格校验完整记录长度、请求窗口、分段连续性和 LAST，并把时间戳和触发索引换算到当前窗口。
- 普通“硬件串口”仍读回完整记录，“演示模式”保持离线生成；板上旋钮只改变模拟幅度，频率和相位仍由 DDS 决定。

## 验证

2026-10-24 完成以下检查：

- UI 回归 36 项通过，协议回归 5 项通过。
- Ruff 检查主程序与启动入口通过，Vulture 联合主程序、入口及测试文件检查通过。
- 模拟串口端到端验证：实际输入幅度翻倍，Vpp/相对幅度和软件模型同步翻倍，不发送 SET_DDS；输入变为直流后清空旧模型；STOP 忽略后到帧；断线禁用参考设置；自动触发不覆盖存档。
- 短窗口分段验证：以完整记录 16384 点、起点 7192、长度 2000 为例，保留原始样本与 OTR，局部触发索引变为 1000，时间戳增加 7192；错误总长度、错误起点及越界样本均被拒绝。
- 使用明确标记的测试数据生成并检查 `tmp/ui-knob-link/linked.png`，布局无重叠或截断。

## 实物采集

验证脚本 `tmp/verify_physical_knob_link.py` 通过 COM12 / 115200 连接现有固件，版本响应 `0100000024102620`。临时启用联动自动快照后获取两帧真实数据，每帧 2000 点、25 MSPS、局部触发索引 1000，时间戳分别为 31436057880、31446059846，证明是两次独立采集。两帧 Vpp 均约 249.08 mV，软件模型约 242 mVpp、100 kHz，有效；OTR=0，CRC/长度/版本/超时解析错误均为 0。

验证后发送 STOP，并恢复 `PC/ui/hardware_profile.json` 中已确认的普通触发配置。未发送 SET_DDS，未烧录 FPGA 或改变模块供电。原始验证记录：`tmp/ui-knob-link/hardware-verification.json`。

尚未验证人工连续转动实体旋钮的过程。当前 UART 是反复快照读回，刷新速度受串口传输和轮询限制，不能视作无延迟连续采样。电位器没有位置回读，因此界面不显示机械角度，也不能将相对幅度当作电位器阻值或绝对模拟增益。
