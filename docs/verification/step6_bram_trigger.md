# 第六步：BRAM 环形缓存和基本触发

实现了真实 RTL 的 16384×16 逻辑双端口 BRAM、带迟滞边沿触发和捕获控制，不再使用第五步的仿真记录缓存代替存储。行为与资源验收使用 Vivado/XSim 2025.2；器件仍为临时 `xc7a35tcsg324-1`，没有开发板预设或最终管脚约束。

## 文件

- `FPGA/rtl/trigger/trigger_edge.sv`：有符号迟滞比较，直接对当前有效样本生成触发条件。
- `FPGA/rtl/capture/capture_bram.sv`：ADC 域写、系统域同步读的简单双端口 BRAM 模板。
- `FPGA/rtl/capture/bram_capture.sv`：循环写、前后触发窗口、帧冻结、跨域所有权及顺序读出。
- `FPGA/rtl/common/scope_pkg.sv`：新增捕获模式、状态和元数据类型，既有 ADC/DDS/存储格式保持原值。
- `FPGA/sim/tb/capture_scenario.sv`、`trigger_scenario.sv`、`tb_capture.sv`：异步时钟、自检、冻结重读、中止/复位和迟滞单元测试。
- `FPGA/scripts/generate_capture_vectors.py`、`audit_capture_traces.py`：独立逐样本触发搜索、时间窗黄金帧和 CSV 审计。
- `FPGA/scripts/run_capture_tb.ps1`、`check_capture_project.tcl`、`check_capture_synthesis.tcl`：可复现回归、原生工程仿真、BRAM 资源证明。

手写 HDL 均为 `1ns/1ps`，采用 `default_nettype none`。新控制逻辑均为各自时钟域的高有效同步复位，没有组合逻辑生成的内部时钟。RAM 内容及 BRAM 的读数据寄存器不复位，外层 `read_valid` 同步复位；无效时读字固定为 `0x07FF`，解码为 0。只有整帧全部写入后才允许读，因此不依赖 RAM 初值。

## 帧定义与数据格式

帧长固定 N=16384，包含 `pre_samples + 1个触发样本 + post_samples`，后触发点数等于 `16383-pre_samples`。触发样本在帧内索引恰为 `pre_samples`，不额外插入或丢掉一个样本。

| 预触发比例 | pre | 触发索引 | post |
|---|---:|---:|---:|
| 0% | 0 | 0 | 16383 |
| 25% | 4096 | 4096 | 12287 |
| 50% | 8192 | 8192 | 8191 |
| 75% | 12288 | 12288 | 4095 |
| 接近 100% | 16383 | 16383 | 0 |

记录字保持 `{OTR,3'b000,raw_code[11:0]}`。触发比较通过原始码计算 `2047-raw_code`，结果为 signed13；OTR 不参与数值解码，但与原始码在同一写入边沿保存。物理指针为 14 位，无符号加减按模 16384 回绕。

触发时锁存当前写地址、ADC 输入样本时间戳及配置。逻辑首地址为 `trigger_address-pre_samples`，按模 16384 回绕。读索引 i 映射到 `start_address+i`，所以地址回绕不改变帧内顺序。

BRAM 只存 16 位字，不扩展为每点存 64 位时间戳。元数据保存首、触发及末样本的 unsigned64 时间戳，逐点读出时间戳按 `first_timestamp+i` 重建，允许模 2^64 自然回绕。因此同一捕获的已接受样本时间戳必须连续：重复或跳号中止捕获并置 `capture_error`，不发布不可信的帧。`sample_valid=0` 的时钟不写 RAM；若下一有效样本时间戳仍连续，可以继续采集。

## ADC 域接口与触发

`module_enable`、`arm`、配置及样本接口均须已处于 ADC 采样域。`arm` 是单个 ADC 周期的请求脉冲，仅 IDLE 或 SINGLE_HOLD 接受；忙碌或已有冻结帧时忽略，防止覆盖。配置在武装时锁存，之后修改外部配置不改变当前帧。系统域命令到 ADC 域的配置握手由后续控制接口集成。

主要配置为 `cfg_mode`（AUTO/NORMAL/SINGLE）、`cfg_rising`、signed13 阈值、unsigned13 迟滞、15 位预触发点数和 32 位自动超时。预触发点数 16384 或更大、无效模式、AUTO 超时为 0 均被拒绝并置错误；新的有效武装或复位清除错误。

迟滞比较先将样本、阈值、迟滞显式扩展到 signed15，避免 `threshold±hysteresis` 溢出。上升沿要求先有有效样本 `<= threshold-hysteresis`，随后有效样本严格 `> threshold+hysteresis`；下降沿反向，先 `>=` 高门限，再严格 `<` 低门限。触发后必须重新到达资格门限才能再次触发。迟滞为 0 时，恒等于阈值的输入不会自行反复触发。

达到所需预历史之前的越限不发布帧；早期越限会消耗比较器的资格，需要再次满足门限条件。预历史仅按有效样本计数，不按空闲时钟计数。

## 模式与所有权

状态流程为 `IDLE → ARMED → POST → FROZEN`。post=0 时由 ARMED 直接冻结。正常情况下写入每个有效样本；触发样本先写入，随后恰好再写 post 个样本，最后一次写入与冻结发生在同一个 ADC 上升沿。

- NORMAL：只接受合格边沿，安静输入可以持续等待。主机释放帧后，使能仍有效则按已锁存配置重新武装。
- AUTO：在预历史满足后，按有效样本计超时。第一个合格等待样本计为 1，第 timeout 个若还没有边沿则自动触发；边沿与超时同拍时优先边沿，`automatic_trigger=0`。
- SINGLE：完成后置 `single_done`，帧读取期间保持冻结。主机释放后进入 SINGLE_HOLD，继续忽略新样本；只有显式新 `arm` 或复位才离开。重新拉高 `module_enable` 本身不重新武装。

冻结之后，RAM、触发位置和元数据保持不变。`module_enable` 在触发前/POST 期间撤销会中止本次捕获且不发布部分帧；撤销使能优先于同拍触发、时间戳检查及最后一个 POST 写入。已经冻结的帧在撤销使能后仍可读，直到释放或复位。

NORMAL/AUTO 的自动重新武装沿用锁存配置。需要改变配置时，应先停用/中止到 IDLE，再显式武装；不能在旧帧仍归主机所有时切换配置并写入。

## 跨时钟域和读口

ADC 域拥有唯一写端口。最后一个样本完成后翻转 request bit，源元数据保持稳定。系统域经两级 `ASYNC_REG` 同步 request，随后锁存整组稳定元数据并置 `frame_ready`。这是 bundled-data 握手，不对多位二进制指针逐位做独立同步。

系统域只有 `frame_ready` 时接受 `read_request`；地址为 14 位帧内索引。请求在系统上升沿接受，该沿后得到对齐的寄存读字、`read_valid`、有符号解码和重建时间戳。读请求允许连续或插入空拍；无效周期不消费数据。

`frame_release` 为单系统周期脉冲，与读请求同拍时优先释放并清掉读有效。ACK 经两级同步返回 ADC 域；在源收到 ACK 前不能重写 RAM。因此最慢读者也不会与写者竞争冻结帧，不依赖双端口 RAM 同地址同时读写的未定义行为。

两个域的复位需协调：都保持有效足够覆盖各自若干时钟，再释放；不支持只复位单侧握手状态而让另一侧继续旧事务。测试覆盖捕获中、冻结中及读事务中的协调复位。行为仿真不模拟亚稳态，后续顶层集成仍需为实际时钟、同步器和 bundled-data 总线配置时序约束并完成物理 CDC/时序验收。

BRAM 推断结构参考 [AMD UG901 2025.2 的双时钟简单双端口 RAM 模板](https://docs.amd.com/r/2025.2-English/ug901-vivado-synthesis/Simple-Dual-Port-Block-RAM-with-Dual-Clocks-VHDL)。本工程对应实现为 SystemVerilog 的单写端口/单寄存读端口。

## 回归矩阵

五个时钟组合：ADC=25/10/50/65 MHz、系统=100 MHz，以及 ADC=65 MHz/系统=7 MHz 的慢读者场景。每种子 62 个有帧用例，包含 9 次不复位的第二帧重新武装，共 71 帧独立黄金数据。

覆盖预触发比例 0/25/50/75/接近100%，触发前零次/一次/多次指针回绕，触发地址 0、1、16383，上升/下降沿，AUTO 超时及同拍边沿优先，配置锁存，过早触发拒绝、迟滞为零、正负阈值、有效空拍与 64 位时间戳回绕。

每个 SINGLE 帧冻结后继续输入 32785 个新样本（超过两整圈），同时由系统域逐点读出，再完整重读一次。释放后仍继续输入新样本，断言不发生 RAM 写入；显式重新武装后才允许第二帧。其他模式也在冻结期持续输入，读者检查元数据始终稳定。

辅助测试覆盖安静 NORMAL、不触发的门限内噪声、触发前/后撤销使能、撤销与边沿同拍、最后 POST 点前撤销、时间戳跳号、非法配置、POST/冻结/读中复位，以及冻结后撤销使能并完整读回的 16384 点帧。迟滞独立单元另外执行每种子 28672 次比较，包括精确边界、零迟滞及大门限/迟滞。

Python 黄金模型逐样本搜索触发并从时间顺序列表截取窗口，不使用 DUT 指针算法或 RTL 函数。TB 和独立 CSV 审计都比较每个字、原始码对应有符号值、OTR、顺序和时间戳；元数据另外核对逻辑起点、触发地址/索引、前后点数、首尾时间和模式。

每种子包含 1,163,264 个独立黄金帧点；加上 SINGLE 完整重读共比较 1,540,096 点，另有辅助整帧 16,384 点。重放和工程仿真不重复计入两种子的独立帧数量。

## 资源验证与运行

```powershell
& 'D:\示波器\FPGA\scripts\run_capture_tb.ps1' -Project
& 'D:\示波器\FPGA\scripts\run_capture_tb.ps1' -Seeds 123,456 -Project
```

默认种子为 20261020、42，首种子自动重放。每次在新 ASCII TEMP 目录从源文件编译；原始输入与黄金帧分别留在 `sim/vectors/capture/<run>/`、`sim/expected/capture/<run>/`。每种子有 11 个 CSV（5 份帧数据、5 份元数据、1 份迟滞轨迹）。重放和原生项目分别要求全部 11 个文件 SHA256 一致，testbench 有 200 ms watchdog 并自动结束。

`-Project` 安全验证并清除已知 `scope_smoke.sim` 生成目录后，从零运行原生 Behavioral Simulation；设计顶层仍为 `scope_hw_top`，仿真顶层为 `tb_capture`。这一步尚未将捕获控制连接到最终板级 UART/命令模块。

随后做两次非工程综合：先证明完整捕获核心使用 BRAM 且不使用 LUTRAM，再单独以任意 16 位输入综合 `capture_bram`，证明完整 16384×16 模板。核心中的三位保留零可被综合器优化为常量，因此实际动态 RAM 宽度是 12 位 raw + 1 位 OTR；逻辑记录仍然完整输出 16 位。单独 RAM 模板保留全部 16 位，不能把保留位优化误判为容量缺失。

综合使用字节哈希一致的 ASCII TEMP 源码与工作目录，结果归档回 `reports/capture/<run>/synthesis/`。中文路径下的早期独立综合未完成，原日志保留；ASCII 暂存复核能够完成综合。此做法也符合 [AMD/Xilinx 教学工程对源路径 ASCII 字符的要求](https://xilinx.github.io/xup_fpga_vivado_flow/lab1.html)，没有移动正式工程或修改 RTL 来绕过功能问题。

报告保留源码 SHA256、命令、工具日志、种子、CSV、逐点审计、综合资源及最终源码快照。资源验证不等同于布局布线时序或实板验收，不创建最终管脚 XDC。

计数说明：`write_pointer` 始终表示下一写地址。固定 N 点整帧从地址 0 写满时，末次写入后 next-pointer 会回到 0；这与帧内物理地址连续 0..16383 的“不跨回绕窗口”并不矛盾。测试同时覆盖未满一圈便中止、恰好一圈冻结、触发前未回绕，以及等待触发导致多次回绕，不用不可能的“固定满深度帧写完后 next-pointer 永不回绕”作验收条件。
