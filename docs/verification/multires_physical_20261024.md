# 板端多分辨率采集：实现与实物验证

> 后续状态：本版本现已完成 Flash 固化、真正断电 QSPI 启动及冷启动多分辨率采集复测，见 [固化报告](multires_flash_20261024.md)。下方“临时 JTAG、未改写 Flash”的叙述保留首次实测时的历史状态。

2026-10-24 已完成 FPGA 板端包络、UART 扩展、PC 能力协商、同帧 ROI、CSV 导出，并临时 JTAG 下载到已连接 EGO1。现有 Flash 未修改；断电后仍恢复此前固化的固件。

## 当前实现

- FPGA 在现有 25 MHz 采样/控制时钟内扫描冻结的 16K BRAM，复用既有 `multires_envelope`。桶数支持 1～800，GUI 开放 100/200/400/800。每桶保留真正 min/max 和全桶 OTR 或值；不以抽点替代包络。
- 新命令 `GET_CAPABILITIES=04`、`READ_ENVELOPE=32`，包络响应 B2；沿用 v1 头、CRC 和分包控制。每桶在线数据为 i16 minimum、i16 maximum、u8 OTR。
- 同一后端读口在原始波形与包络扫描间互斥，SINGLE 不能在传输期间释放该帧。STOP 完成已提交包的 CRC，再取消后续包并排空在途读取。
- PC 在新 build 的能力标记下查询能力；旧固件不探测未知命令，自动回退完整原始帧与 PC 包络。原波形、触发、DDS 命令兼容。
- 多分辨率页面默认获取板端概览及触发附近 2048 点原始 ROI。STOP 后移动选区，使用既有 READ_WAVE offset/count 按需读取，最多 2048 点。ROI 时间轴始终相对完整帧触发点，可在触发点任一侧。
- 包络、ROI 严格校验来源时间戳、采样率、触发索引、长度、序号、标志和数据范围。新 SINGLE 替换板端旧记录后，拒绝混入另一帧的 ROI。PC 历史缓存最近 16 帧概览及各帧当前已缓存 ROI。
- 测量和 FFT 明确标为来自当前原始 ROI；未缓存区域会清空细节曲线。顶部 CSV 在此模式保存原始 ROI 并带窗口偏移/完整帧长度，新增独立板端概览 CSV 保存桶范围、极值和 OTR。
- 启动入口支持 `--multires`，例如 `启动示波器界面.cmd --multires`。普通时域与 FFT 采集路径保持原有完整记录/联动短窗口策略。

## 仿真与实现

权威构建报告：`FPGA/reports/board/20261024_203912/manifest.json`。

- 正式板级顶层、原生 UART 引脚、ADC/DAC 行为模型参与仿真；普通与上电预设测试均 PASS，分别逐点核对完整 16384 点冻结记录及 UART 首尾读出。
- 新多分辨率板级测试：800/400/100 桶合计 1300 桶与独立记录的 ADC 时间线逐桶一致；跨三个串口分包的 1024 点 ROI 逐点一致；非法桶数、错误长度、越界读取返回正确错误；包中 STOP、后续 PING 和再次包络读取通过。所有线上包独立复核 CRC。
- 首次 `20261024_203057` 和独立重跑 `20261024_203706` 的 XSim 终端均为 `TEST_PASS tb_scope_board_multires`；最初 Python 审计误把前一请求的续包当成后一请求首包，原 FAIL 清单保留。修正审计必须以匹配请求序号的 FIRST 包开始后，两套原始追踪均独立通过。正式报告校验所有生产 RTL、暂存副本、时钟 HDL 与板级测试台一致后复用首套仿真，重新执行综合和实现；没有修改 RTL 来绕过失败。
- Vivado 2025.2 综合、布局布线、bitstream 生成 PASS；setup WNS=10.477 ns、hold WHS=0.034 ns。LUT 4826/20800（23.20%），FF 3817/41600（9.18%），BRAM 7/50（14%），DSP 9/90（10%）。没有 DRC Error 或 Critical Warning。
- DRC 警告并未清零：报告仍有与旧版一致的 69 项警告，含 RAM 异步控制与 DSP 流水建议。CDC 报告仍包含已有模块开关/复位控制路径的 critical 项（CDC-1=746、CDC-13=10；旧版为 750/10）；不能据此宣称完整 CDC 签核通过。未改变时钟、外部引脚、供电安全控制或放宽 XDC 来取得通过。
- PC 原有 65 项与新增 7 项契约测试合计 72 项通过；Ruff 无告警。新增测试覆盖分包与序号回绕、单点尖峰/OTR、ROI 两端/不包含触发点、过期帧、取消、旧固件回退、UI 缓存边界及概览 CSV 极值/索引保真。

## 实物验证

用户确认 SW0 OFF、外部 ADC/DAC 5 V 关闭后，通过原有脚本核对目标 `1234-tulA`、IDCODE `0362d093` 并临时 JTAG 下载，DONE=1。JP2 保持 QSPI。随后用户确认外部模块供电稳定并将 SW0 OFF→ON，再开始采集。

- 发布目录：`FPGA/output/multires_921600_20261024/`。
- bitstream SHA256：`c226a64fb3287b270d7a6bdd7688e1da249cb42edf8fc8b15aee6776f26bcee4`。
- 新固件 build=`0xA0261024`，COM12 / 921600，设备回报 25 MSPS、16384 点；能力 flags=1、800 桶、2048 点 ROI。
- 实测原始证据：`FPGA/reports/multires_hardware/20261024_204934/verification.json`，同目录保留六帧完整原始码与真实界面截图。验证入口 `tmp/verify_multires_device.py`。
- 共六次独立冻结帧，桶数 100/200/400/800/800/800。每次先收包络和 ROI，再不触发新采集地读回同一冻结帧全部 16384 点作 oracle；3100 个桶的 min/max 与 OTR 全部精确一致，初始原始 ROI 逐点一致。
- 每帧追加读取 `[0,512)`、`[7000,8024)`、`[14336,16384)` 三段原始 ROI，合计 21504 点逐点一致。旧帧被新 SINGLE 替换后，跨帧 ROI 确认被 PC 拒绝。
- 信号约 100 kHz、136.75 mVpp；PC CRC/长度/版本/超时错误为 0，FPGA 八项协议/UART 错误计数增量为 0，后端错误为 0。
- 800 桶 + 2048 点原始 ROI 的响应数据为 8436 B，含分包头/CRC；采集过程中加上 SINGLE 和一次状态响应后，实际收到 8541 B。完整原始波形响应为 33956 B，数据量约为原来的四分之一。
- 三次 800 桶采集与回传耗时为 153.56/153.53/153.74 ms（中位约 153.56 ms）；相同冻结帧完整原始读回约 384.4～384.9 ms，单独读回时间不包含采集。两者计时范围不同，不能直接声称精确端到端加速比。

当时硬件为单通道 25 MSPS、16384 点 BRAM；此次为临时 JTAG 运行。后续 Flash 固化及校准状态见 2026-10-25 的相应报告。

新版可见界面已重启为 COM12 / 921600 的实物联动模式，启动在多分辨率页；正式串口后台线程执行 SINGLE 得到板端 800 桶及 2048 点 ROI。原生鼠标将选区从触发附近拖到约 +150 µs 后，同一冻结帧读取并显示帧索引 11026～13072 的 2047 个原始样本，首帧时间戳保持不变、未执行新 SINGLE，证明 UI 的按需 ROI 回读路径也实际可用。

随后在可见界面运行连续采集，观察到至少 88 次快照、16 条历史缓存，PC/FPGA CRC、超时、RX 溢出及后端错误均为 0。验证结束点击 STOP，保留最新多分辨率快照供用户查看。
