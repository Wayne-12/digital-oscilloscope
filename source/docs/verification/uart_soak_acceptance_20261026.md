# 两小时长稳及多档 UART 验收（离线功能交付）

> 2026-10-26 19:46 实物更新：按用户要求仅执行功能短测，COM12 / 921600、固件 `0xA0261026` 得到 `SHORT_PASS`。30 秒连续采集 137 帧，加上恢复验证共 139 帧；CRC、完整性、超时及 FIFO 错误新增为零，原配置恢复成功。详见 [实物短测报告](uart_physical_smoke_20261026.md)。两小时长稳及其他档位仍待另行安排，稳定档位清单仍为空。下文离线交付记录保留原阶段范围。

本轮只编写、测试离线程序，未打开真实串口、下载 FPGA 或写入 Flash。实物两小时长稳与 UART 档位验收仍待用户接入设备后执行；目前可宣传的本轮实物稳定档位为空。既有短时实测不替代本轮长稳。

## 验收规则与实现

入口：[PC/tools/run_uart_acceptance.py](../../PC/tools/run_uart_acceptance.py)，核心：[uart_acceptance.py](../../PC/protocol/uart_acceptance.py)。不依赖 Qt；离线模式只用 Python 标准库，实物模式额外使用已安装的 pyserial。

1. 在明确指定的端口、波特率握手，核对固件 build、配置读回和多分辨率能力。禁止自动降速、重试掩盖错误和清零解析器。记录固件文件 SHA256、设备标识、条件、随机种子和源码 SHA256。文件哈希由操作员指定的实际加载文件计算，不能据此自动证明板上配置身份；同时核对 build 并保留下载记录。
2. STOP 后保存真实配置，临时采用确定可触发的欠幅配置。DDS 需已启用，程序不改变其波形、幅度、频率或输出使能。模块与闭环未准备好、信号跨度不足 4 ADC 码时失败。
3. PING 回显使用固定种子伪随机字节，轮换 64、508、1024 字节负载，逐字节比对。至少验证 **1 MiB 单向负载回显**并持续至少 **600 秒**，两个条件必须同时满足；另外记录含头及 CRC 的实际 TX/RX 字节数。
4. 随后以 25 MSPS 连续请求快照至少 **7200 秒**。每次检查 800 桶包络、2048 点 ROI；首帧及每十帧读取 16384 点完整原始记录，并逐桶比较覆盖区域。完整记录读取后比较 FPGA 精确 sum、square_sum 和极值；有能力 bit2 的新固件还逐帧解码测量与 1024 点 FFT 摘要，核对冻结帧身份。FFT 数值精度另由已有专项验收负责。
5. 严格检查 CRC、请求响应和分包序号、FIRST/MORE/LAST、长度、样本偏移、时间戳、采样率、触发索引、样本保留位、OTR、重复或陈旧快照、额外或噪声字节。检查 FPGA 八类错误计数相对基线的增量，以及已收请求数与主机请求数是否一致；支持 u16 序号及 u32 计数自然回绕。已有非零基线如实记录，验收要求区间内零新增错误。
6. 两小时结束后另做 STOP→重新采集、关闭串口→原档重新连接→重新采集；不重置板卡或计数器。最终恢复原触发并逐字节比较完整配置，DDS 与记录参数始终不改。任何失败或 Ctrl+C 都尝试恢复，保留失败/中断报告；强制结束进程或断电只能保留上次 RUNNING 检查点，不能承诺恢复。

每档默认至少约 **2 小时 10 分钟**，另外包含握手、恢复检查与必要的字节配额时间。普通 UI 的自动回退行为不用于验收。两小时统计排除后续恢复检查，`soak_captures` 与包含恢复阶段的总 `captures` 分开。

本系统按请求冻结快照，不是持续将 25 MSPS ADC 流传到 PC。“丢帧”在这里指已请求的响应、分包或捕获不完整、乱序或重复；未请求的 ADC 区间不算丢帧，不能宣传为连续无死区采样。系统没有温度传感器，温度现象由操作员人工记录。

## 无硬件操作

双击 [启动UART离线验收.cmd](../../启动UART离线验收.cmd)，默认检查 921600 档；或者在项目根目录运行：

```powershell
.\.venv-ui\Scripts\python.exe PC/tools/run_uart_acceptance.py --offline --baud 115200
.\.venv-ui\Scripts\python.exe PC/tools/run_uart_acceptance.py --offline --baud 921600
```

离线端点通过正式 encode/Parser 和重组器交换字节，使用虚拟时钟计入 UART 线速并模拟每次采集后的 10 秒间隔，几秒完成模型两小时流程，报告同时保存实际墙钟耗时。模型只实现能力 3 的配置/包络/原始码端点；能力 7 的测量/频谱处理路径由专门故障注入测试覆盖。这些结果均为软件数据，不证明硬件速率、模拟精度、USB 稳定性、温升或真实时间运行能力。

## 用户接入实物后执行

优先验收实际使用的 921600，以及确有需要的 115200；不要求凑齐四档，不追求更高波特率。固件 UART 为编译时固定值，更改 PC 下拉框不会改变板端波特率。现有构建入口只允许 115200/921600，当前新分析发布包为 921600；230400/460800 仅验证了软件端，未生成对应发布固件。不要用旧的无 GET_CONFIG 固件执行本脚本。115200 如需本轮功能，应另行构建、验证和临时加载同功能 115200 固件后独立运行；本轮没有代为构建或烧录。

按既有接线与供电流程准备 OUTA→IN，固定旋钮并记录位置，确认模块供电与 SW0 使能、DDS 已启用且输出幅度适当。关闭普通示波器 UI，以免占用串口。加载本轮 921600 分析固件并留存加载记录后，示例命令如下（端口与条件替换为实际值）：

```powershell
.\.venv-ui\Scripts\python.exe PC/tools/run_uart_acceptance.py --hardware --baud 921600 --port COM12 --device-id EGO1-01 --firmware FPGA/output/analysis_1024_921600_20261026/scope_analysis_1024_25m.bit --expected-build 0xA0261026 --conditions "OUTA-IN; 25MSPS; 100kHz sine; DDS10%; gain固定位置已拍照; 电源5V; 室温与预热情况另记"
```

先做短测定位问题时可加 `--duration 30 --uart-duration 2 --min-echo-bytes 4096`，结果为 `SHORT_PASS`，稳定档位清单为空；实物正式验收必须重新运行默认配额，不累计拼接短测。`--output-dir` 可指定一个尚不存在的目录，默认保存到 `PC/acceptance_runs/`。恢复失败时停止后续测试，检查报告中的 `restore_error`，重新连接并确认配置后再操作。

每档最后人工补记：电源与线缆是否变化、旋钮是否固定、模块温度/异常现象、是否出现设备复位或 USB 掉线。物理复位与真正断电重启是独立人工步骤，本脚本只自动验收串口重新连接和采集重启，不替代既有冷启动报告。

## 结果与宣传口径

每次独立目录包含：

- `report.json`：每约 30 秒原子保存状态，记录模型/实物来源、时长、CRC/超时/序号错误、FPGA 基线与增量、请求与完成数、不完整捕获数、OTR、恢复和结论。
- `events.jsonl`：带北京时间的阶段与进度记录；失败原因为报告中的 `error`。
- `first_full_wave.bin`、`last_wave.bin`：小端 u16 原始 ADC+OTR 码；报告列出首帧身份。`last_rx.bin` 保存最近最多 64 KiB 接收字节，`last_tx.bin` 保存最后一个请求，供排错；它们可能包含恢复阶段数据，并非失败瞬间的完整线路抓包。
- `stable_rates.json`：只有 **hardware-uart + PASS + 默认时长/负载达标 + 零错误 + 恢复成功** 才含非空 `qualified_bauds`，限定设备、固件哈希和记录条件。`OFFLINE_PASS`、`SHORT_PASS`、`RUNNING`、`FAIL`、`INTERRUPTED` 不产生稳定档位。

最终指标只写非空清单中的档位并链接其原始报告，例如“本设备、该固件与所列接线条件下，921600 bit/s 完成 ≥1 MiB/≥10 分钟回显及连续两小时快照验收，CRC、请求及分包完整性错误、超时和 FIFO 溢出新增为零”。不能推导其他固件、其他设备或未测档位稳定，也不能写“最高稳定波特率”。

## 本轮离线验证

故障注入回归位于 [test_uart_acceptance.py](../../PC/tests/test_uart_acceptance.py)，覆盖 CRC 损坏、整包消失、分包缺失、额外噪声、重复响应、回显不一致、提前 LAST、波形元数据错误、FPGA 溢出/复位、序号/计数回绕、旧时间戳、OTR/保留位错误、同帧摘要身份及数值错误、Ctrl+C 恢复与恢复失败、短测/离线证据不能晋级。

最终 PC 回归共 102 项通过（含 16 项新增验收测试），见 [回归日志](../../tmp/uart_soak_full_pc_tests_20261026.log)。Qt DLL 在沙箱内加载失败，完整回归在沙箱外用模拟设备运行；未打开真实串口。新增模块、入口、测试和 UI 提示的 Ruff 检查见 [静态检查日志](uart_soak_offline_20261026/ruff.log)。

115200、230400、460800、921600 四档模型均完成 ≥600 秒回显与 ≥7200 秒快照流程，报告的 `source=offline-model`，`qualified_bauds=[]`。最终证据位于 [四档结果汇总](uart_soak_offline_20261026/final/summary.json)，各档原始记录保存在同目录的 `baud_档位/`；根目录下同名旧目录为开发时的前一次离线记录，不作最终源码证据。
